# WhisperX orchestre Whisper, l'alignement mot à mot et pyannote sur le pod.
# Les versions sont verrouillées : toute mise à jour CUDA/Torch se fait dans
# une PR dédiée, validée par la construction de l'image RunPod.
#
# torch 2.8 : torch <= 2.5.1 est touché par CVE-2025-32434 (exécution de code
# au chargement d'un modèle piégé, même avec ``weights_only=True``), corrigée
# en 2.6 ; 2.8.0 corrige aussi les failles publiées depuis. torch et
# torchaudio sont épinglés ensemble. Pyannote 3.x dépend encore de
# ``torchaudio.AudioMetaData``, absent de torchaudio 2.9+ (déprécié en 2.8) :
# ne pas dépasser 2.8 tant que pyannote reste en 3.x. Le Dockerfile installe
# explicitement les roues CUDA 12.8 correspondantes depuis PyTorch avant ce
# fichier ; les versions ci-dessous empêchent pip de les remplacer ensuite.
torch==2.13.0
torchaudio==2.8.0
# whisperx 3.7.9 : dernière version compatible pyannote 3.x (la 3.8 passe à
# pyannote 4, autre API et autre modèle de diarisation). Elle exige
# torch~=2.8.0 et Python >= 3.10 (celui de l'image). Les versions 3.3.3 à
# 3.4.x sont à éviter : elles réimposaient ctranslate2<4.5.0 (cuDNN 8).
whisperx==3.7.9
# torch 2.8.0 installe nvidia-cudnn-cu12 9.10 (cuDNN 9). ctranslate2 4.4.x
# exige cuDNN 8 — absent de l'image, d'où un crash natif « Could not load
# library libcudnn_ops_infer.so.8 » qui tue le processus (pas une exception
# Python) et fait redémarrer le conteneur. ctranslate2 >= 4.5.0 utilise
# cuDNN 9 : épingler cette version ici explicitement pour ne pas dépendre du
# minimum transitif de whisperx.
ctranslate2==4.5.0
# pyannote.audio 3.4.0 : même code que la 3.3.2 (même API
# ``use_auth_token``, mêmes modèles), avec des bornes hautes sur ses
# dépendances pyannote.*. Dernière version 3.x.
pyannote.audio==3.4.0
# pyannote 3.x importe matplotlib à l'initialisation mais ne le déclare
# pas dans ses dépendances publiées.
matplotlib>=3.7,<4
# pyannote 3.x ne déclare que huggingface_hub>=0.13 mais appelle encore
# hf_hub_download(..., use_auth_token=...), un argument que huggingface_hub
# 1.0 a supprimé (remplacé par `token`). Sans borne haute, pip installait
# la 1.x et la diarisation échouait à la première transcription :
# « hf_hub_download() got an unexpected keyword argument 'use_auth_token' ».
# C'est transformers (non épinglé par whisperx) qui tirait la 1.x : ses
# versions 5.x exigent huggingface_hub>=1.3, ses 4.5x huggingface_hub<1.0.
# Les deux bornes vont donc ensemble ; borne basse de hub : celle de
# transformers 4.56+ (et hf_xet, ci-dessous, n'est utilisé qu'à partir de
# la 0.30).
transformers>=4.48,<5
huggingface_hub>=0.34,<1.0
# Backend de transfert accéléré de huggingface_hub (téléchargement des
# modèles Whisper) : sans lui, HF_XET_HIGH_PERFORMANCE (voir handler.py /
# pod_server.py) n'a aucun effet et on retombe sur un simple GET HTTP.
hf_xet>=1.0
